# Traces hold only product work, and usage counts each token once

Langfuse exports through a tracer provider of its own, so no other library's span can parent an observation or join a trace. Startup capability probes and the startup sweep open no observation. Usage reaches Langfuse as mutually exclusive buckets, and an embedding reports its billable tokens. The `langfuse_export_external_spans` setting is gone.

## Status

Accepted and implemented. It amends [ADR 0017](0017-observability-span-contract.md): the vocabulary loses `probe-image-capability` and `recover-ingestion`, the usage rule becomes exclusive buckets, and the consequence that ingestion's per-chunk calls surface as traces of their own no longer holds. The deployment is a development one, so nothing is migrated: stored traces keep their old shape, and a configuration that still sets the removed key fails validation like any unknown key.

## Context

The local development project held 1,310 traces, and 1,228 of them were noise: 1,222 roots named `embed-text` (599, of which 86 were release 2.0.23's detached ingestion embeddings and the rest the embedding probe), `probe-image-capability` (402) or `recover-ingestion` (221), and 6 traces with no name. The usage on the traces that were work was wrong in two further ways. Four defects:

- **Startup work was traced as work.** Each start of the API and of the MCP server emitted about five root traces: two `probe-image-capability` (the chat model's image-capability probe), two `embed-text` (the image query and the fused document of the embedding probe that workspace creation runs), and one `recover-ingestion` (the sweep). The sweep's trace was empty in 221 of 221 cases: 3 ms, no children. These are capability checks and a safety net, not work a reviewer reads.
- **Six traces had no name.** With no OpenTelemetry provider registered, Langfuse registers its own as the process-global one. FastAPI 0.142's request span (scope `fastapi`) and the MCP SDK's spans (scope `mcp-python-sdk`) then became recording parents of every observation opened inside a request or an MCP call, and the export filter that kept only `langfuse-sdk` spans dropped those parents. An observation whose parent Langfuse never received is a trace with no root and no name. A script reproduced it: in a FastAPI route, the observation's parent was the ASGI span.
- **Usage counted the cache twice.** The adapter sent `input` as the provider's prompt tokens, which include the cached ones for OpenAI, DeepSeek and Gemini, beside `input_cached_tokens`. Stored data read `{input: 673, output: 39, total: 712, input_cached_tokens: 512}`. [Langfuse's rule](https://langfuse.com/docs/observability/features/token-and-cost-tracking) makes usage keys mutually exclusive buckets: `input` excludes every `input_*` key, a token sits in exactly one key, and `total` is their sum. Langfuse normalises the usage of its own SDK integrations and of `gen_ai.usage.*` attributes, but flat `usage_details`, which is what the adapter sends as `langfuse.observation.usage_details`, is stored unchanged and must already be exclusive. `input` should have been 161. The adapter also kept key tuples of its own beside the dialect helpers in `engine/ai/providers/base.py`, and the two already disagreed: the adapter missed `input_tokens_details.cached_tokens` of the Responses wire.
- **Embeddings carried no usage.** 2,891 of 2,891 `embed-text` observations had none; the merged provider usage only rode in `output`.

Cost was 0 on every generation and embedding, because no Langfuse model definition matches the aliases the observations carry (`deepseek-flash`, `voyage-multimodal-3.5`). That is project configuration, not code.

## Decision

**Langfuse owns an isolated tracer provider.** `init_tracing` builds an OpenTelemetry `TracerProvider` and passes it to `Langfuse(tracer_provider=...)`. The process-global provider stays the no-op default, so the request spans of FastAPI and the MCP SDK do not record, parent nothing and appear in no trace; an observation opened in a request is a root. The provider is built as the SDK builds its own default: `langfuse.release` and `langfuse.environment` on its resource, and a trace-id ratio sampler only when `langfuse_sample_rate` is below 1. `shutdown_tracing` shuts the client down, which flushes, and then the provider. With no foreign span left to remove, `should_export_span` and `langfuse_export_external_spans` are deleted.

**Startup work opens no observation.** The image-capability probe, the image-embedding probe and the recovery sweep are not units of work. `probe-image-capability` and `recover-ingestion` leave the vocabulary. The embedder separates running its requests from observing them: the probe sends the same two requests through the unobserved part, and ordinary `embed_*` calls are observed as before. The sweep keeps its `pipeline_recovery()` coordination and its logging. Model work LightRAG performs outside any root, such as the rebuild after a delete that other documents share, is still exported when it happens.

**Usage keys are exclusive buckets.** `input` is the prompt minus the prefix-cache hit, `input_cached_tokens` is the hit (only when above zero), `output` is the completion with its reasoning, and `total` is the provider's stated total or, when it states none, the sum of the buckets. The adapter reads every dialect through `provider_input_tokens` and `provider_cache_hit_tokens`, which were already the product's one statement of it, plus `provider_output_tokens` and `provider_total_tokens`, and keeps no key list of its own. Anthropic's `input_tokens` excludes `cache_read_input_tokens` and `cache_creation_input_tokens`: the helpers add both back and the subtraction takes the reads out, so cache writes stay inside `input`. An `embed-text` observation reports `input` and `total` as the provider's `total_tokens`, the billable number (Voyage multimodal states `text_tokens`, `image_pixels`, `video_pixels` and `total_tokens`).

**Cost stays the operator's.** Langfuse infers cost from a Model definition whose match pattern fits the observation's `model` attribute, which is the model alias, priced per usage key (`input`, `output`, `input_cached_tokens`). DlightRAG computes none and holds no price; [Observability](../observability.md#cost) says how a project defines one.

## Considered options

- **Drop every observation that has no root.** Rejected. It would remove the startup noise, and it would also hide real spend: model calls LightRAG makes outside a Run or an ingestion root surface as roots, and a reviewer needs to see them. The noise is removed at its source.
- **Keep `recover-ingestion` as a root opened only when the sweep has work.** Rejected. Whether it has work is LightRAG's decision from its own document-status storage, so DlightRAG would mirror those status predicates and follow them across upgrades.
- **Check for pending documents first and skip the sweep when there are none.** Rejected for the same reason. The native sweep already is that check: it took 3 ms in the 221 measured cases.
- **Keep the global provider and the export filter.** Rejected. It is the arrangement that produced the unnamed traces, and a filter cannot repair a parent it has removed.
- **Keep `langfuse_export_external_spans`.** Rejected. With an isolated provider there are no external spans to export, so the key could do nothing; under the global provider, turning it on would have put every FastAPI, HTTP-client and database span in the tree.
- **Send the provider's counters and let Langfuse normalise them.** Rejected. Langfuse subtracts the cache for its SDK integrations and `gen_ai.usage.*` attributes; the flat `usage_details` attribute DlightRAG sends is stored unchanged.
- **A usage key of its own for Anthropic's cache writes.** Deferred. Writes are priced differently from plain input, but nothing reads them yet, and a price table the operator has not written would not use the key.
- **Compute cost from a price table in the repository.** Rejected. Prices are the operator's and change; ADR 0017 already holds that cost is never computed here.

## Consequences

- Starting the API or the MCP server adds no trace. Neither the rebuild after a shared-entity delete nor a non-empty sweep has occurred in the data, so whether such calls ever surface as roots is open.
- No span another library opens in the process can parent an observation. `tests/unit/test_observability_wire.py` reads what a real client built by `init_tracing` exports: an observation opened under a FastAPI request is a root and the request span is never exported, and the usage keys for OpenAI chat, DeepSeek, Responses and Anthropic payloads hold each token once and sum to `total`. The embedding probe and the recovery sweep are asserted where they run (`test_multimodal_embedding.py`, `test_workspace_rag_runtime.py`). A parent that arrives over the wire, a W3C `traceparent` in an MCP call's `_meta`, would still parent an observation opened inside that call; roots open in the worker that owns the work, not in the request, and no such parent appears in the data.
- Existing data is not repaired. The stored observations keep their old `input`, and the noise traces stay until someone deletes them.
- Cost still reads 0 for an alias until the project has a definition for it.
- Langfuse keeps one resource manager per public key for the life of the process, and a client built with a key it has already seen reuses the first one's provider. A process therefore initialises tracing once and shuts it down once; initialising the same key again after `shutdown_tracing()` would export nothing. The tests give each client its own key.
- `opentelemetry-sdk` is a declared dependency; it was already installed as Langfuse's.
- Gemini and Cohere embedding responses do not state `total_tokens`, so those embeddings still carry no usage keys. What they do state stays in `output.usage`.
